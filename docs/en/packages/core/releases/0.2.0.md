# Aster Core 0.2.0

Status: **Draft; not yet published**.

This version makes every icon an explicitly identified treatment of a glyph and groups collection
selections by treatment. It also reuses recognised canonical definitions without repeating their
construction, while retaining complete validation for unknown values.

- Breaking change: require `identity.variant` on every definition and replacement identity;
  `namespace` remains optional and no treatment is inferred.
- Breaking change: replace flat collection aliases with non-empty treatment groups. Collection
  alias/treatment maps are frozen and prototype-free; `members` remains a flat ordered list of
  concrete definitions.
- Compatible capability: expose `IconGlyphIdentity`, `IconVariantMap` and
  `Icon.variantPropertyName()` for explicit families and canonical treatment-property naming.
- Compatible capability: reuse the exact output of `Icon.define()` when the same loaded Core copy
  recognises it. Clones, deserialised values and compatible foreign outputs still receive full
  validation; freezing an arbitrary object does not establish recognition.
- Compatible correction: strengthen own-data validation and reduce repeated text and collection
  construction work without weakening isolation or immutability.

Core has no runtime dependencies.

## Migration

Add the actual treatment to authored definitions, for example
`identity: { namespace: "example", name: "camera", variant: "outline" }`. Do not assume unrelated
artwork is Outline merely because its previous identity omitted a variant.

Replace `icons: { camera: CameraOutline }` with
`icons: { camera: { outline: CameraOutline } }`, and select
`InterfaceIcons.icons.camera.outline` instead of `InterfaceIcons.icons.camera`. Each group must
select definitions of the same glyph with property names derived from their treatment slugs:
`filled-dotted` becomes `filledDotted`. Duplicate concrete identities remain invalid.
Use `Object.keys()` or other static object operations rather than inherited methods on the maps.

The [collection guide](../collection/index.md) owns the complete membership contract.
For repeated use, retain and share the result of `Icon.define()` rather than reconstructing it
inside each render; [definition reuse](../definition/runtime/index.md#reusing-definitions) explains
the recognition boundary.
