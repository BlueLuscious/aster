# Aster CLI 0.2.0

Status: **Published on 26 October 2026 (UTC)**.

Source commit: `b33ebef3dd44103bb6e346f8aa419326df1aea9a`.

Registry: [`@luscious-garden/aster-cli@0.2.0`](https://www.npmjs.com/package/@luscious-garden/aster-cli/v/0.2.0)

Approved archive SHA-256: `a0b04faee03124d7bd7ea7c6176373e1d8d6be8d3d878eb2e472b7fb5cb4379b`.

This version distinguishes glyph discovery from operations on concrete treatments and gives
diagnostics explicit supporting facts. It also makes human results consistently structured while
retaining compact JSON and the existing local/global executable model.

- Breaking change: require a treatment in concrete icon requests and provider identities, such
  as `aster/camera@outline`; a glyph name never silently selects Outline.
- Breaking change: rename collection discovery/result `icons` to `memberIdentities`, including
  custom providers and JSON. General icon arrays and Core's `icons` map are not renamed.
- Breaking change: replace diagnostic `related` strings with discriminated `details` whose
  permitted shape follows the stable diagnostic code and category. Human failures label those
  facts beneath `Details:` rather than print an anonymous `Related:` sequence.
- Breaking change: normalise human sequences to one entry per line, two-space ownership
  indentation and `(none)` for applicable empty values. Embedded controls are quoted and escaped
  visibly rather than interpreted as structural terminal content.
- Compatible capability: add `list glyphs`, `show glyph` and the exact `list icons --glyph` filter,
  preserving provider provenance and explicit ambiguity handling without loading artwork.
- Compatible correction: strengthen provider/member consistency and own-data isolation, and
  avoid repeated membership work in catalogue queries.

Requires Core `^0.2.0`, Icons `^0.3.0` and SVG `^0.2.0`. Node `>=24.10.0 <25` remains required.

## Migration

Use glyph commands to discover a family and explicit icon identities for show, export or review.
For a project-installed CLI:

```sh
pnpm exec aster list glyphs
pnpm exec aster show glyph aster/camera
pnpm exec aster list icons --glyph aster/camera
pnpm exec aster show icon aster/camera@outline
```

The [shell guide](../shell/index.md#installation-and-invocation) owns local/global invocation and
version-source selection; the [catalogue guide](../catalogue/index.md) owns provider-scoped discovery.

Custom providers must populate `memberIdentities` with complete concrete identities and return
definitions/collections following the [Core migration](../../core/releases/0.2.0.md#migration).
Code reading collection results must use the same renamed field; no `icons` compatibility alias
is retained there.

Replace positional reads of `diagnostic.related` with handling of the code-specific
`diagnostic.details` and its `kind`. The [diagnostic contract](../command/index.md#diagnostic-details)
owns all supported shapes, including families that carry no details. Stable diagnostic codes,
stream routing and exit-status rules are retained.

Automation parsing human text must account for its revised layout and visible control escapes;
prefer structured `--json` results. JSON remains compact, but the collection and diagnostic data
changes above still apply. No `--pretty` or `--indent` option is introduced.
